# v39.0 军师控制优化详解

## 问题背景

在v36.0版本中，军师LLM控制存在以下问题：
1. **军师几乎不工作**：`should_advice()` 使用 `pygame.time.get_ticks()` 导致时间计算错误
2. **边界卡住**：主公频繁卡在地图边界（如y=20或y=980）
3. **指令stuck**：军师指令长时间不更新
4. **LLM超时**：35B模型响应慢，10秒超时太短

## 优化内容

### 1. 修复时间基准（v36.02）

**问题**：`pygame.time.get_ticks()` 返回从 `pygame.init()` 开始的毫秒数，初始值约为0-100ms。`should_advice()` 中 `now - last_advice` 的差值永远小于5秒，导致军师几乎不工作。

**修复**：
```python
# 修改前
now = pygame.time.get_ticks() / 1000

# 修改后
import time as _time
now = _time.time()
```

**效果**：军师现在每5秒正常给出建议。

### 2. 降低建议频率（v36.02）

**问题**：每2秒一次建议太频繁，军师建议权重低，吕布没有时间执行。

**修复**：
```python
# 修改前
if now - self.last_advice >= 2.0:

# 修改后
if self.last_advice == 0 or now - self.last_advice >= 5.0:
```

**效果**：单条建议权重提高，吕布有足够时间执行。

### 3. 后处理修正（v36.03-v36.05）

**问题**：LLM生成的指令可能让主公靠近或卡在边界。

**修复**：添加 `_post_process_cmd` 方法：
```python
def _post_process_cmd(self, cmd, game_state):
    MARGIN = 150  # 边界余量
    
    # X轴边界检测
    if px < MARGIN:
        dx = 0.8  # 强制向右
    elif px > WIDTH - MARGIN:
        dx = -0.8  # 强制向左
    
    # Y轴边界检测
    if py < MARGIN:
        dy = 0.8  # 强制向下
    elif py > HEIGHT - MARGIN:
        dy = -0.8  # 强制向上
    
    # 角落对角线处理
    if px < MARGIN and py < MARGIN:
        dx, dy = 0.7, 0.7  # 右下
```

**效果**：主公可以脱离边界进入安全区域。

### 4. 增强提示词（v36.04）

**问题**：LLM不知道主公当前精确位置，生成指令可能让主公靠近边界。

**修复**：在提示词中添加边界警告：
```python
if px < 150:
    boundary_info.append(f"紧急：主公已在地图最左侧(x={px})，必须立即向右移动！")

user_prompt = (
    f"主公精确位置：({px}, {py})\n"
    f"{boundary_text}\n"
    f"【重要规则】\n"
    f"1. 绝对不要靠近地图边界！\n"
    f"2. 最佳战斗位置是中心区域(800,500)附近\n"
)
```

**效果**：LLM生成的指令更智能，避免边界。

### 5. 传递游戏状态（v36.05）

**问题**：`give_advice()` 调用时没有传递 `game_state`，导致 `_post_process_cmd` 无法获取主公位置。

**修复**：在 `tank_battle_deluxe.py` 中传递完整游戏状态：
```python
_game_state = {
    "player": {"x": player.rect.centerx, "y": player.rect.centery, ...},
    "player_camp": {"x": player_camp.x, "y": player_camp.y, ...},
    "enemy_camp": {"x": enemy_camp.x, "y": enemy_camp.y, ...},
}
ADV_CHANNEL.give_advice(..., _game_state)
```

**效果**：`_post_process_cmd` 可以正确获取主公位置进行边界修正。

### 6. fallback边界修正（v36.05）

**问题**：LLM失败时调用 `_fallback_advice()`，生成的指令没有边界修正。

**修复**：
```python
self.last_cmd = self._post_process_cmd(self.last_cmd, {
    "player": {"x": player_x, "y": player_y}
})
```

**效果**：fallback指令也有边界保护。

### 7. 调试信息（v36.05）

**新增**：添加边界检测调试输出：
```python
if px < MARGIN or px > WIDTH - MARGIN or py < MARGIN or py > HEIGHT - MARGIN:
    print(f"[DEBUG] 边界检测: 主公在({px},{py})，修正前指令: dx={dx}, dy={dy}")
    print(f"[DEBUG] 边界修正: 主公在左侧(x={px})，强制向右 dx=0.8")
```

**效果**：可以实时监控边界修正是否生效。

## 调试记录

### Bug 1: 军师不工作
**现象**：军师几乎不给建议，主公由Pilot随机控制
**根因**：`should_advice()` 使用 `pygame.time.get_ticks()`，初始值为0，差值永远<5秒
**修复**：改用 `time.time()`
**验证**：军师现在每5秒给出一次建议

### Bug 2: 边界卡住
**现象**：主公频繁卡在地图边界（如y=20或y=980）
**根因**：
1. `_post_process_cmd` 没有接收到 `game_state`
2. `_fallback_advice` 也没有边界修正
**修复**：
1. 在 `tank_battle_deluxe.py` 中传递 `_game_state`
2. 在 `_fallback_advice` 中添加边界修正
**验证**：主公可以脱离边界进入安全区域

### Bug 3: 指令stuck
**现象**：军师指令长时间不更新（如stuck在67.3s）
**根因**：LLM响应慢，35B模型生成128 tokens需要>10秒
**修复**：
1. 延长超时到20秒
2. 减少max_tokens到64
3. 添加 `llm_pending` 超时保护（30秒强制重置）
**验证**：指令每5-10秒更新一次

### Bug 4: Camp对象没有rect属性
**现象**：游戏崩溃，`AttributeError: 'Camp' object has no attribute 'rect'`
**根因**：传递 `_game_state` 时使用了 `player_camp.rect.centerx`
**修复**：改用 `player_camp.x` 和 `player_camp.y`
**验证**：游戏正常启动
